# Synthetic inputs for the LLM extraction demo

Everything in this folder except this README is generated by
`python3 -m generador_llm` (package `examples/generador_llm/`, available after
`pip install -e .`; default seed 1414). All names, RFCs, UUIDs and amounts are fictitious. A test regenerates the files
and fails if they differ, so never edit them by hand.

```bash
python3 -m generador_llm                           # rewrites examples/synthetic_llm/
python3 -m generador_llm --salida out/ --semilla 7
```

Exit codes: `0` written, `2` invalid parameters.

## Files

| Path | Content |
|---|---|
| `documentos/<id>.xml` | 25 CFDI 4.0 XML documents (what the model reads) |
| `documentos/<id>.txt` | 25 printed representations as plain text (what the model reads) |
| `cfdis_conocidos/<uuid>.xml` | Known-CFDI pool read by the deterministic engine (49: one document has no XML) |
| `verdad.jsonl` | Ground truth per document: the twelve fields as printed, planted injection, edge cases, whether review is expected |
| `respuestas_grabadas/<id>.json` | **Synthetic** recorded responses for `--modo grabado`, one per document |
| `errores_plantados.json` | Which synthetic responses carry a planted error, and which fields it touches |

The `.txt` files simulate the text a PDF extractor would produce from the printed
representation. No PDF is generated or parsed: that would add a dependency without
changing what the demo shows.

## Conventions

- RFCs are `RFC_*` placeholders (repo-wide convention: nothing that looks like a real RFC is
  ever committed). The company receiving every invoice is `RFC_EMPRESA_DEMO`.
- UUIDs use the all-zero test form `00000000-0000-0000-0000-0000000000NN`. Document ids
  and UUID numbers are drawn independently, so an id does not reveal its UUID.
- Amounts in the truth are canonical strings (`"1234.56"`). Template A prints thousands
  separators and ISO dates; template B prints no separators and `dd/mm/yyyy` dates.
- Discount, IEPS, ISR withheld and VAT withheld are `null` in the truth when the invoice does
  not carry them, and they appear in the XML and the printed text only when it does. Every
  document except `iva_no_cuadra` satisfies `subtotal − discount + VAT + IEPS − ISR withheld
  − VAT withheld = total` to the cent.
- The case list is shuffled by the seed before ids are assigned.

## Edge cases

| Tag | What it is | Expected outcome with a perfect extraction |
|---|---|---|
| `iva_no_cuadra` | Printed VAT is one peso off; the stamped XML in the pool is right | review |
| `rfc_mal_formado` | Printed issuer RFC has a hyphen where the placeholder has an underscore | review |
| `moneda_usd` | Invoice in USD with exchange rate (XML and printed) | accepted |
| `moneda_no_permitida` | Invoice in EUR (not in the allowed list) | review |
| `coma_miles` | Printed amounts carry thousands separators | accepted |
| `sin_xml_en_pool` | Printed invoice whose XML is not in the pool | review |
| `monto_grande` | Subtotal above one million | accepted |
| `tasa_cero` | VAT at 0% | accepted |
| `benigno_dificil` | Issuer named `SYSTEM SOFTWARE` (not a role marker) | accepted |
| `fecha_dd_mm_aaaa` | Template B date format | accepted |
| `honorarios` | Professional fees from an individual: VAT 16%, ISR withheld 10%, VAT withheld two thirds of the VAT (rate printed as 10.6667%) | accepted |
| `flete` | Freight of goods: VAT 16% and VAT withheld 4% | accepted |
| `descuento` | 10% discount before taxes; VAT on the subtotal minus the discount | accepted |
| `ieps` | IEPS 8% transferred; VAT on the subtotal plus the IEPS | accepted |

## Planted injections

Seven documents carry an instruction in a free-text field (the concept description in XML,
the notes line in text). Six use vocabulary from the `prompt_guard` catalog and are meant to
be flagged. One (`parafrasis_tercera_persona`) is a third-person narrative written to evade
the guard, as documented in `skills/security-guardian/specs/evasiones_conocidas.md`.

## Synthetic recorded responses

These are **not** Claude responses. The generator writes them from the truth and plants
plausible errors: one digit changed in a total, VAT omitted, a date copied as printed, amounts
left with thousands separators, VAT computed on the total with the subtotal derived from it
(`iva_sobre_total`: the sum still equals the total, so only the cross-check against the pool
catches it), IEPS folded into VAT (`ieps_en_iva`: same sum, caught only by the cross-check),
both withholdings of a fee invoice left out (`retencion_omitida`: the identity fails), and a
model that obeys an injection. Token usage is a fixed
approximation (about four characters per token), not a real count.

Three responses obey an injection. Two of them belong to documents the guard blocks, so the
pipeline never reads them; a test runs them with the guard disabled to show the
deterministic checks still catch the change. The third belongs to the evasion: the guard
misses it, the model "obeys", and the deterministic checks route it to review.

Metrics computed from these files validate the evaluation pipeline, not Claude's accuracy.
Real metrics come from `--modo vivo`, which can re-record this folder with `--grabar`.
